# Core Tenets
- **Single Source of Truth (SSOT) & Reuse-First:** Consolidate logic into canonical modules; generalize and reuse existing classes/primitives before creating new ones. Always import canonical SSOT modules directly — never import legacy merged module aliases (`config`, `symbols`, `instruments_config`, `keys.apikeys`, `accepted_order_persistence`, `order_outcomes_log`, `order_rollback`, `lock.file_lock`, `lock.trade_cooldown`, `providers.binance_filters`, `providers.http_resilience`, `providers.replay_clock`).
- **Separation of Concerns (SoC) & Layered Class Design:** Keep files small, modular, and strictly isolated to a single domain responsibility across architectural layers (*Transport/Providers*, *Persistence/Cache*, *Order Gateway & Guards*, *Strategy & Exit Engine*, *Orchestration/Supervision*). Solve cross-cutting bugs and rules inside the responsible layer or base class (`BaseSpotMixin`, `CacheManagerInterface`, `Instrument.place()`, `order_guard.py`) so all callers inherit the behavior automatically, rather than scattering per-caller `if/else` patches across bots.
- **Zero Static Fallbacks (Fail-Fast Init):** Never hardcode magic numbers, thresholds, intervals, URLs, or symbol lists in Python, and never provide fallback defaults or synonym guessing for static config keys. Validate required settings at load/init (`raise ValueError`/`KeyError`). Reserve fallbacks strictly for runtime operational resilience (WS->REST, missing live trend, fail-closed guards).
- **Formulaic Parameter Correlation Over Redundant Config Keys:** Always identify mathematical relationships between correlated parameters (polling cadences, TTLs, reference windows, staleness bounds, scaling/sizing limits) and derive dependent values via explicit formulas from a single primary anchor variable in the SSOT layer (e.g., `resolve_crypto_executor_interval_sec()`, `resolve_derived_telemetry_intervals()`) rather than setting multiple correlated raw numbers in config files or pre-calculating them manually.
- **Symmetry & Naming Grammar:**
  - Maintain strict directional (`BUY`/`SELL`, `BULL`/`BEAR`, `RISK_ON`/`RISK_OFF`) and cross-venue (`binance`, `kraken`, `hyperliquid`, `t212`) symmetry via shared primitives (`opposite_side()`, `profit_diff_pct()`, `select_extreme_reference()`, `get_window_cfg()`, `get_dynamic_window_sec_cfg()`, `venue_fee_cap_quantity()`).
  - Follow uniform domain naming across classes, files, getters, and config keys:
    - *Caches:* `Cache<Qualifier><Domain>Manager` ↔ `cache_<qualifier>_<domain>.json[l]` ↔ `get_<qualifier>_<domain>_manager()`
    - *Intelligence:* `<domain>_collector.py` (`<domain>_collect.json`) ↔ `<domain>_evaluator.py` (`<domain>_eval.json`)
    - *State & Heartbeats:* `<module_name>_state.json` (`cachedb/state/`) ↔ `<module_name>.heartbeat` (`cachedb/system/heartbeat/`)
    - *Guards & Config:* `<Category>Guard` (`GO1`, `GT_S/M/L`, `G_PROF`, `G_QLIMIT1/2`, `GI_*`, `GLLM1..3`) and symmetric `<SIDE>_*` / `<HORIZON>_*` keys.
