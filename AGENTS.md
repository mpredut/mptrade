# Core Tenets
- **Single Source of Truth (SSOT) & Reuse-First:** Consolidate logic into canonical modules; generalize and reuse existing classes/primitives before creating new ones. Always import canonical SSOT modules directly (never re-export compatibility shims).
- **Pragmatic Simplicity (No Speculative Edge-Case Bloat):** Do not add defensive branches, extra state, or recovery plumbing for rare/theoretical edge cases (e.g., mid-write process kill, local disk-write failure, sub-millisecond race) if the guard costs more than 1 line of code. Keep the happy path and realistic venue/network failures simple and linear; if a low-probability corner case would require >1 line, skip it or ask the user first.
- **Separation of Concerns (SoC) & 3-Tier Polymorphic Class Design:**
  - Keep files small, modular, and strictly isolated to a single domain responsibility across the architecture layers below.
  - Follow a 3-tier polymorphic class hierarchy (Level 1 pure abstract base contract -> Level 2 domain-specific abstract bases -> Level 3 concrete leaf classes registered in a declarative factory/registry).
  - Solve cross-cutting bugs and rules inside the responsible base class or shared layer (`CacheManagerInterface`, `Cache*ManagerBase`, `MarketDataProvider`, `AssetSessionPolicy`, `BaseSpotMixin`, `Instrument.place()`, `order_guard.py`) so all callers inherit the behavior automatically, rather than scattering per-caller `if/else` patches across bots.
- **Horizontal & Vertical Scalability (Open-Closed, Strict DAG, Pure Compute & Idempotency):**
  - *Horizontal (Open-Closed / Registry-Driven):* Extend venues, asset classes, guards, caches, collectors, and strategies via polymorphic subclasses and declarative registries (`instrument_registry.py`, `AssetSessionPolicy`, `guard_hierarchy.py`, `CacheFactory`, `MarketDataProvider`) -- never by scattering `if venue/strategy/asset_class == ...` branches across core modules.
  - *Vertical (Strict Acyclic Layering):* Enforce one-way dependencies (`cachepaths` -> `state_io` -> `core/*` (`botcore` facade) -> `cacheintegrity` / `instrument_registry` / `pricewindow` -> `providers` -> `caches` -> `instrument` / `order_guard` / `order_lifecycle` -> `strategies` -> `orchestrators`); lower layers must never import higher layers (`providers/` must never import `caches`), and sibling cache modules (`cacheaccount.py`, `cacheprice.py`, `cachetrend.py`) must remain mutually independent.
  - *Pure Compute, Idempotency & Bounded I/O:* Keep sizing, guard, survival-guard, exit, prompt-view, and regime evaluation pure/deterministic over `(snapshot, config)` for seamless live/replay reuse; ensure state transitions and retries are idempotent, precompile regexes at module scope, and avoid per-symbol disk/network I/O inside hot loops.
- **Producer-Consumer Decoupling (Single-Writer / Read-Only Consumers):** `cacheManager.py` is the sole `data_sync_mode="producer"` for price/trend/account caches, alongside dedicated snapshot collectors (`priceAnalysis.py`, `market_monitor/price_watcher.py`, `intelligence/*_collector.py`, `intelligence/macro_analyzer.py`) and single-worker `order_retry_worker.py` (retry queue). Trading bots (`tradeall.py`, venue bots), guards, and evaluators act strictly as read-only consumers (`data_sync_mode="disk_reader"` / `"live_reader"`, `ensure_account_cache_readers()`) and must never spawn duplicate sync threads, duplicate WebSocket streams, or mutate producer-owned caches.
- **Zero Static Fallbacks (Fail-Fast Init):** Never hardcode magic numbers, thresholds, intervals, URLs, model names, or symbol lists in Python, and never provide fallback defaults or synonym guessing for static config keys (`raise ValueError`/`KeyError` at load/init). Reserve fallbacks strictly for runtime operational resilience (WS->REST, missing live trend, fail-closed guards).
- **Formulaic Parameter Correlation Over Redundant Config Keys:** Always identify mathematical relationships between correlated parameters (polling cadences, TTLs, reference windows, staleness bounds, scaling limits) and derive dependent values via explicit formulas from a single primary anchor variable in the SSOT layer (e.g., `resolve_crypto_executor_interval_sec()`, `resolve_derived_telemetry_intervals()`) rather than setting multiple correlated raw numbers in config files.
- **Symmetry & Naming Grammar:**
  - Maintain strict directional (`BUY`/`SELL`, `BULL`/`BEAR`, `RISK_ON`/`RISK_OFF`) and cross-venue (`binance`, `kraken`, `hyperliquid`, `t212`) symmetry via shared primitives (`opposite_side()`, `profit_diff_pct()`, `select_extreme_reference()`, `venue_fee_cap_quantity()`).
  - Follow uniform domain naming across classes, files, getters, and config keys:
    - *Caches:* `Cache<Qualifier><Domain>Manager` <-> `cache_<domain>_<venue>.json[l]` / `cache_<qualifier>_<domain>.json[l]` <-> `get_<qualifier>_<domain>_manager()`
    - *Intelligence:* `<domain>_collector.py` (`<domain>_collect.json`) <-> pure stateless `<domain>_evaluator.py` (periodic analyzers emit `<domain>_eval.json`)
    - *State & Heartbeats:* `<module_name>_state.json` (`cachedb/state/`) <-> `<module_name>.heartbeat` (`cachedb/system/heartbeat/`)
    - *Guards & Config:* `<Category>Guard` (`GO1`, `GT_S/M/L`, `G_PROF`, `G_QLIMIT1/2`, `GI_*`, `GLLM1..3`) and symmetric `<SIDE>_*` / `<HORIZON>_*` keys.
