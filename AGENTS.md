# Core Tenets
- **Single Source of Truth (SSOT) & Reuse-First:** Consolidate logic into canonical modules; generalize and reuse existing classes/primitives before creating new ones. Always import canonical SSOT modules directly (never legacy aliases in `botcore._MERGED_MODULE_TARGETS`).
- **Separation of Concerns (SoC) & Layered Class Design (Model: `cacheManager.py`):**
  - Keep files small, modular, and strictly isolated to a single domain responsibility across layers (*Transport/Providers*, *Persistence/Cache*, *Order Gateway & Guards*, *Strategy & Exit Engine*, *Orchestration/Supervision*).
  - Follow `cacheManager.py` (`CacheManagerInterface` base contract → specialized domain subclasses → `CacheFactory` / `get_*_manager()` accessors) as the reference blueprint for class hierarchies.
  - Solve cross-cutting bugs and rules inside the responsible base class or layer (`CacheManagerInterface`, `BaseSpotMixin`, `Instrument.place()`, `order_guard.py`) so all callers inherit the behavior automatically, rather than scattering per-caller `if/else` patches across bots.
- **Producer–Consumer Decoupling (Single-Writer / Read-Only Consumers):** Dedicated background daemons and collectors (`cacheManager.py`, `tradeall.py`, `priceAnalysis.py`, `kraken/kraken_cachemanager.py`, `market_monitor/price_watcher.py`, `intelligence/globaltelemetry_collector.py`, `intelligence/macro_analyzer.py`, `order_retry_worker.py`) act as the sole producers that fetch, compute, and atomically publish `cachedb/` snapshots. Trading bots, guards, and evaluators act strictly as read-only consumers (`start_sync=False` / `ensure_account_cache_readers()`) and must never spawn duplicate sync threads, duplicate WebSocket streams, or mutate producer-owned caches.
- **Zero Static Fallbacks (Fail-Fast Init):** Never hardcode magic numbers, thresholds, intervals, URLs, or symbol lists in Python, and never provide fallback defaults or synonym guessing for static config keys (`raise ValueError`/`KeyError` at load/init). Reserve fallbacks strictly for runtime operational resilience (WS->REST, missing live trend, fail-closed guards).
- **Formulaic Parameter Correlation Over Redundant Config Keys:** Always identify mathematical relationships between correlated parameters (polling cadences, TTLs, reference windows, staleness bounds, scaling limits) and derive dependent values via explicit formulas from a single primary anchor variable in the SSOT layer (e.g., `resolve_crypto_executor_interval_sec()`, `resolve_derived_telemetry_intervals()`) rather than setting multiple correlated raw numbers in config files.
- **Symmetry & Naming Grammar:**
  - Maintain strict directional (`BUY`/`SELL`, `BULL`/`BEAR`, `RISK_ON`/`RISK_OFF`) and cross-venue (`binance`, `kraken`, `hyperliquid`, `t212`) symmetry via shared primitives (`opposite_side()`, `profit_diff_pct()`, `select_extreme_reference()`, `venue_fee_cap_quantity()`).
  - Follow uniform domain naming across classes, files, getters, and config keys:
    - *Caches (Model):* `Cache<Qualifier><Domain>Manager` ↔ `cache_<qualifier>_<domain>.json[l]` ↔ `get_<qualifier>_<domain>_manager()`
    - *Intelligence:* `<domain>_collector.py` (`<domain>_collect.json`) ↔ `<domain>_evaluator.py` (`<domain>_eval.json`)
    - *State & Heartbeats:* `<module_name>_state.json` (`cachedb/state/`) ↔ `<module_name>.heartbeat` (`cachedb/system/heartbeat/`)
    - *Guards & Config:* `<Category>Guard` (`GO1`, `GT_S/M/L`, `G_PROF`, `G_QLIMIT1/2`, `GI_*`, `GLLM1..3`) and symmetric `<SIDE>_*` / `<HORIZON>_*` keys.
